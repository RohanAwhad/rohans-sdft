# Chunked LM Head — reverse-KL loss (`chunked_head.py`)

> (rohan) TODO: make sure this is correct!

## Role

Computes the reverse-KL loss `KL(student ‖ teacher)` for one completion, with a
**chunked memory profile** so long completions (thinking sequences hit 4k–8k
tokens) don't OOM. It runs as a Megatron-Core `GPTModel` **`output_processor`
hook**, so the LM head is applied **once** per microstep on the completion
hidden states (the module's single-call path — probe-validated, no deadlock).

## Communication contract (how the trainer uses it)

`make_kl_processor(...)` (`chunked_head.py:113`) builds the hook:

```
make_kl_processor(
    prompt_len: int,
    completion_ids: list[int],
    teacher_log_probs: torch.Tensor,      # (C, V) bf16, detached, on device
    eos_token_id: int | None,
    device: torch.device,
    row_chunk: int = 128,
    rollout_log_probs: torch.Tensor | None = None,   # (C,) fp32, NaN = masked
    is_weighting: bool = True,
    is_cap: float = 2.0,
) -> processor                       # MCore output_processor callable
```

The trainer calls it as (`trainer.py:401-411`):

```
loss, metrics = model(
    input_ids=input_ids,
    position_ids=position_ids,
    attention_mask=None,
    output_processor=kl_processor,
)
```

Contract:
- `C` = `len(completion_ids)` = `teacher_log_probs.size(0)`.
- The processor is built from the **prompt/completion tokenization**, not the
  model; it slices the completion hidden states itself
  (`hidden_states[prompt_len-1 : prompt_len+C-1, 0]`, `chunked_head.py:156`).
- Returns `(loss: scalar tensor with grad attached, metrics: dict[str, float])`.

## How it works

- LM head called once on the completion rows; logits `(C, V)` bf16.
- `ChunkedRowKL` (`chunked_head.py:31`) — an `autograd.Function` — processes
  **row chunks** (`ROW_CHUNK=128`, `KL_CHUNK=2048`):
  `KL(p_s ‖ p_t) = Σ_v p_s(v)·(log p_s(v) − log p_t(v))`, summed over rows and
  divided by `C` (row-mean) in the processor (`chunked_head.py:170`).
- Per-row `policy_logp` / `critic_logp` are returned detached for metrics.

## Importance-sampling weighting (vLLM rollout correction)

The rollout is generated by vLLM, whose proposal distribution can drift from
the training policy (weight staleness between syncs, sampling params). The
reverse-KL objective assumes samples come from the current policy — when the
proposal differs, the per-sequence loss is rescaled by a truncated importance
sampling (TIS) weight, same scheme as TRL's `DistilTrainer`.

`compute_is_weight(policy_logp, rollout_log_probs, cap)` (`chunked_head.py:28`),
called in the processor after the row loop (`chunked_head.py:172-181`):

```
r_t   = exp(policy_logp_t − rollout_log_probs_t)     # per-token ratio
r_t   = clamp(r_t, max=cap)                          # TIS truncation
w     = mean over valid tokens of r_t                # per-sequence scalar
loss  = loss * w                                     # detached
```

- `policy_logp` — the detached per-token log-probs under the **current** policy
  (already returned by `ChunkedRowKL`; no extra forward pass needed).
- `rollout_log_probs` — the per-token log-probs of the **rollout** (vLLM)
  distribution, captured at generation time; `NaN` marks tokens that were never
  sampled (adapter force-close inserts, chat-template artifacts like
  `<|im_end|>`) and are excluded from the mean.
- The weight is **detached** — it rescales the already-computed KL loss; no
  gradient flows through it.
- When `rollout_log_probs` is `None` or `is_weighting=False`, the loss is
  byte-identical to the unweighted path.

## Analytic backward

`backward` (`chunked_head.py:60-68`):

```
A   = log p − t                    # per-token
g   = grad_kl · p · (A − kl_row)   # total derivative
```

`kl_row` carries the full derivative of the per-row KL — a naive
detached-denominator softmax would leave a spurious `+p` error term. Only
per-row scalars are retained (`ctx.save_for_backward(z, teacher, d, kl_row)`),
so the fp32 `(C, V)` log-softmax is never materialized for backward. Peak
student-side memory drops ~3 GB vs the old retained-(C,V) path (see module
docstring).

## Metrics returned (`chunked_head.py:183-207`)

Computed under `no_grad`; `signal = critic_logp − policy_logp`:
- `sdpo/signal_mean`, `sdpo/signal_std`, `sdpo/len_signal_mean`
- `sdpo/policy_logp`, `sdpo/critic_logp`
- `sdpo/eos_signal_mean`, `sdpo/eos_logp_mean`, `sdpo/eos_logratio_mean` — only
  when the completion contains `eos_token_id`
- `is/ratio_mean`, `is/ratio_min`, `is/ratio_max` — per-sequence TIS weight
  stats (masked mean / min / max of the clamped per-token ratios)
- `is/logp_diff_mean` — mean `|policy_logp − rollout_log_probs|` over valid tokens
- `is/clip_rate` — fraction of valid tokens whose ratio hit the `is_cap` bound
- (`is/*` metrics only present when `rollout_log_probs` is provided and
  `is_weighting` is on)

## Hard invariants

- **Head called once per microstep** — never twice (single-call path avoids
  deadlock; FSDP handles the head gradients natively).
- **`teacher_log_probs` must be detached** — the KL is against the frozen/EMA
  teacher; gradients flow only through the student logits.
- **`C` consistency** — `teacher_log_probs.size(0)` must equal
  `len(completion_ids)`; `prompt_len` must match the position where the
  completion starts in `input_ids`.
- **`rollout_log_probs` must be `(C,)`** — a length mismatch raises a
  `ValueError` (`chunked_head.py:173-177`); the trainer aligns the list before
  building the tensor (NaN-pad with a warning, `trainer.py:356-368`).
- **The IS weight is detached** — it never contributes gradient; only the KL
  loss carries gradient.
